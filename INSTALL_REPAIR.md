# Что было не так в загруженном архиве

Прогнал реальную `npm run build` (не только `tsc`), сверил файлы с
последней рабочей версией. Нашёл 3 проблемы:

## 1. КРИТИЧНО: `app/globals.css` физически отсутствовал

Файл был просто удалён (случайно, судя по всему) — из-за этого:
- сборка падала намертво (`Module not found: Can't resolve './globals.css'`,
  `layout.tsx` его импортирует);
- даже если бы собралось, сайт был бы без единой стилизации.

**Восстановлен** — положил актуальную версию со всеми темами/анимациями
из последней рабочей сборки.

## 2. Три файла-дубля не в той папке

Нашёл `app/contracts/tick/route.ts`, `app/contracts/negotiate/route.ts`,
`app/contracts/backfill/route.ts` — **не** `app/api/contracts/...`, а
именно `app/contracts/...` (без `api`). В Next.js App Router `route.ts`
работает как живой эндпоинт в ЛЮБОЙ папке, не только под `/api/` — так
что это были не просто мёртвые файлы, а реально доступные (но забытые и
устаревшие — более старая версия кода, без части фиксов) дублирующие
эндпоинты на `/contracts/*` вместо `/api/contracts/*`.

**Удалил** — правильные версии на `app/api/contracts/...` остались
нетронутыми, сборка это подтвердила (в списке роутов дублей больше нет).

Сам факт разделения `contracts.ts`/`contractsShared.ts` на клиентскую и
серверную часть (без чего раньше падала сборка с `Can't resolve 'fs'`) —
проверил отдельно: сделано верно, работает, я ошибочно принял разницу в
названии файла за проблему при первом взгляде — это не баг.

## 3. Логотипы Widzew Łódź и Zagłębie Lubin

Нашёл причину в `data/clublogos.ts`. Польская буква **Ł/ł** ("l с
чертой") — это ОТДЕЛЬНЫЙ код Юникода, а не "базовая буква + диакритика",
поэтому `.normalize("NFD")` её не разбирает и не убирает. Она проваливалась
в `replace(/[^a-z0-9]+/, "-")` как "непонятный символ" и превращала слаг
в бессмыслицу:

- `Zagłębie Lubin` → было `zag-ebie-lubin`, стало `zaglebie-lubin`
- `Widzew Łódź` → было `widzew-odz`, стало `widzew-lodz`

Добавил явную замену `ł→l` до нормализации (и на всякий случай `đ→d` —
сербская/хорватская/вьетнамская буква той же природы, могла давать
похожий баг для других клубов).

**Важно**: это чинит слаг на стороне кода. Если файлы в Supabase Storage
называются как-то иначе (не `zaglebie-lubin.png`/`widzew-lodz.png`) —
логотипы всё ещё не найдутся, тут я могу проверить только код, не
содержимое твоего бакета. Если после этого фикса лого всё равно не
показываются — скинь список файлов в бакете `clubs`, сверю точные имена.

## Проверено

Прогнал `npm run build` (полную сборку, не только typecheck) — чисто,
0 ошибок, 0 предупреждений.

## Как накатить

Просто заменить `app/globals.css` и `data/clublogos.ts`, удалить папку
`app/contracts/` целиком (НЕ `app/api/contracts/` — ту не трогать).
